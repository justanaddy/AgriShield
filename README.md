# AgriShield — Precision Agriculture Decision Support System

Belagavi district, Karnataka (15.8497°N, 74.4977°E) — Rice/Paddy demo field.

Scope: satellite NDVI, weather, and ML-based crop risk prediction with
alerting. IoT soil-sensor hardware/simulation and the disease-detection
module are not part of this build.

## Setup

### 1. Backend

```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt

copy ..\.env.example ..\.env        # edit values as needed

cd ml
python train.py                  # generates models/crop_risk_model.pkl
python evaluate.py               # sanity check (RMSE, risk classification)

cd ..
python -m uvicorn app.main:app --reload
```

Visit `http://localhost:8000/docs` for interactive API docs.

### 2. Enabling real NDVI (Google Earth Engine)

```bash
pip install earthengine-api
earthengine authenticate --project=agrishield-499212
```

Then in `.env`:
```
GEE_ENABLED=true
GEE_PROJECT_ID=agrishield-499212
```

Restart the backend. `/ndvi/current`, `/ndvi/timeseries`, and
`/ndvi/heatmap` will now return live Sentinel-2 data. If GEE is
unreachable or `GEE_ENABLED=false`, the app automatically falls back to
realistic demo values — the rest of the app works identically either way.

### 3. Weather

No setup needed — `/weather/*` endpoints call the free Open-Meteo API
directly (real data, no key required). Falls back to demo values only if
Open-Meteo is unreachable.

### 4. Frontend

```bash
cd frontend
npm install
npm run dev
```

Visit `http://localhost:5173`. The Vite dev server proxies `/api/*` to
`http://localhost:8000`.

## Soil Moisture Input

There is no IoT/sensor hardware or simulator in this build. The live
`soil_moisture` input now comes from Open-Meteo (`get_current_soil_moisture()`
in `app/services/weather_service.py`), which reports shallow (0-7cm)
volumetric water content (m3/m3) - a different physical quantity from the
training data's NASA POWER root-zone wetness percentage (GWETROOT). To keep
live inputs on a comparable scale to what the model was trained on, the raw
Open-Meteo value is linearly rescaled from its typical 0.05-0.45 range onto
the training data's observed 78-91% range. This is a disclosed approximation,
not a unit conversion, and is documented as a limitation. It can be
overridden per-request via the `soil_moisture` field in a `POST /predict`
request body. Falls back to a demo value if Open-Meteo is unreachable, same
as the other live sources.

## Tech Stack

- Backend: FastAPI, SQLAlchemy (SQLite by default, swap to Postgres+TimescaleDB), scikit-learn, XGBoost
- Satellite: Google Earth Engine (Sentinel-2 NDVI)
- Weather: Open-Meteo (real-time + historical, free, no key)
- Frontend: React + Vite, Recharts, Leaflet (via CDN)
